- **Protected behavior**: All existing intraday, simulation, dashboard, mobile, replay, `/trade-execution`, and `/paper-trades` behavior must remain unchanged. Legacy `stock-watcher.db` is never touched.

## Autopilot Implementation Decisions

| # | Ambiguity | Decision | Rationale |
|---|---|---|---|
| AD-C01 | SHA-256 in domain vs infrastructure | `StrategyConfig.computeConfigHash` imports `node:crypto` directly. `createHash` is deterministic and is not on the domain forbidden list (only `crypto.randomUUID`, `Date.now`, `Math.random` are forbidden by architecture test). | FD business-logic-model.md §Strategy Schema Validation; NFR DET-004 |
| AD-C02 | DataVersionId / BacktestRunId generation | UUIDs are generated by the application service using `node:crypto.randomUUID()` and passed to domain constructors as pre-validated strings. Domain never calls `randomUUID`. | Architecture test pattern; NFR DET-010 |
| AD-C03 | Application service layer location | `server/portfolio/application/strategy/` is a new sibling directory to `domain/`, `ports/`, `infrastructure/`, and `adapters/`. The architecture test already checks acyclicity across all `server/portfolio/` files. | NFR Design LC-U03-12 through LC-U03-18 |
| AD-C04 | Resilience-wrapped port injection | Application services accept raw port interfaces (MarketDataPort, etc.) via constructor injection. The resilience layer wraps raw adapters before injection in U07 composition. Application services do not import infrastructure directly. | Dependency inversion; acyclic constraint from NFR Design |
| AD-C05 | Provider fakes in tests | All 7 provider fakes live in `tests/portfolio/strategy/support/provider-fakes.ts`. Each fake is a class implementing the port interface with configurable response, error, and delay simulation. | NFR-U03-TEST-011; PAT-U03-014 |
| AD-C06 | Preset config constants | Three preset strategy configs are defined as frozen constant objects in `server/portfolio/domain/strategy/strategy-presets.ts`. Values taken verbatim from `aidlc-docs/inception/requirements/strategy-presets.md`. | SV-005, SV-015 |
| AD-C07 | DOMAIN_FAILURE_CODES extension | New U03 failure codes are appended to the existing `DOMAIN_FAILURE_CODES` array in `server/portfolio/domain/errors/failure.ts`. This extends the U01 union without breaking existing consumers. | Consistent failure pattern; TypeScript const-array |
| AD-C08 | New identifiers extension | New branded identifier types (BacktestRunId, DataVersionId, DataRecordId, CorporateActionId, StrategyVersionEventId) are added to `server/portfolio/domain/shared/identifiers.ts` following the exact same pattern. Parse functions are exported from `server/portfolio/index.ts`. | U01 identifier pattern |
| AD-C09 | Architecture test additions | The existing `tests/portfolio/architecture.test.ts` is modified to add: (a) U03 domain/ports files forbidden-import check; (b) 140 U03 rule evidence count test. | Consistency with U01 architecture test structure |
| AD-C10 | ProviderHealthRegistry | Implemented as a simple in-memory Map inside `circuit-breaker-registry.ts`. Exposed via a `getProviderHealth(providerIdentity: string)` method rather than as a separate file. | Logical coupling; NFR-U03-RES-008, OBS-003 |
| AD-C11 | Benchmark scope | `benchmark/portfolio-strategy.ts` benchmarks three subsystems: eligibility scan (1,000 instruments), signal scoring (1,000 instruments with all factors), and snapshot assembly. Reports p50/p95/max and heap delta. Does not benchmark provider calls (those are mocked in benchmarks). | NFR-U03-PERF-001, PERF-003, PERF-006, PERF-022 |
| AD-C12 | Float z-score representation | Z-score component values in SignalSnapshot are stored as regular `number` (not bigint, not string). The NaN/Infinity guard runs at time of assignment, not at type level. TypeScript `exactOptionalPropertyTypes` catches undefined propagation. | NFR-U03-DET-002, NFR Design PAT-U03-003 |
| AD-C13 | Strategy events separate from aggregate | `server/portfolio/domain/strategy/strategy-events.ts` defines all U03 domain event types independently (not inside strategy-version.ts) to avoid an event→aggregate cycle, following the pattern in U01 `domain-events.ts`. | LC-U03-10 design; U01 pattern |
| AD-C14 | Test package.json | No new test `package.json` is created under `tests/portfolio/strategy/`. The existing `tests/portfolio/package.json` (`{ "private": true, "type": "module" }`) covers all subdirectories. | Existing pattern |

### Step 4: Strategy Config Value Object

**File**: `server/portfolio/domain/strategy/strategy-config.ts` (create)

- `StrategyConfigHash`: branded 64-char hex string type
- `StrategyHorizon`: `'SHORT' | 'MEDIUM' | 'LONG'`
- `createStrategyConfig(raw: unknown): DomainResult<{ config: StrategyConfig; hash: StrategyConfigHash }>`:
  - Safe JSON parsing (reject prototype-polluting keys, unknown top-level fields)
  - Validate all 15 SR rules
  - Compute `horizon` from `routineFrequency` (SR-015)
  - Compute `configHash` via SHA-256 of canonical UTF-8 JSON (keys alphabetically sorted, no indentation)
  - Return frozen immutable config + hash, or first validation failure
- `strategyConfigsEqual(a: StrategyConfig, b: StrategyConfig): boolean` — compares by hash

Import: `node:crypto` for `createHash`; constants.ts; identifiers.ts; failure.ts; result.ts

**Dependency**: Steps 1, 2, 3
**Rules**: SR-001 through SR-015
**Stories**: US-007
